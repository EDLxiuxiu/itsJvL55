# 语言规范与算法说明

## 1 语言范围

单一全局作用域；区分大小写。只支持常量声明与变量声明，不支持表达式、函数和控制结构。各类型有固定教学存储大小。

标识符形式：`[A-Za-z_][A-Za-z0-9_]*`。保留字：`const int real char bool true false`。允许以下划线开头是本系统自定规则。

## 2 声明文法

```text
Program      → Declaration* END
Declaration  → const Type ID = Literal ;
             | Type ID OptionalInit ;
OptionalInit → = Literal | ε
Type         → int | real | char | bool
Literal      → Sign Number | Number | CHAR | BOOL
Sign         → + | -
Number       → INT | REAL
```

END 为单独一行的 `*`。它只在字符常量和注释之外起结束作用；结束后只允许空白和合法注释。源程序用换行辅助错误恢复，正常声明可在同一行或跨行书写。

## 3 字面量

| 类别 | 形式 | 例子 |
| --- | --- | --- |
| 十进制整数 | 一串十进制数字，前导零按十进制 | 0、010、100 |
| 十六进制整数 | 0x/0X 后跟至少一位十六进制数字 | 0x2A、0XFF |
| 实数 | 数字、小数点、可选小数位、可选指数 | 12.、0.5、1.2e+3、1.2E-2 |
| 字符 | 单引号包围一个 Unicode 码点或一个转义字符 | 'A'、'优'、'😀'、'\n' |
| 布尔 | true 或 false | true、false |

实数指数可以带正负号，也可以不带；但尾数必须有小数点，所以 `12e2` 和 `.12` 不合法。这是本系统定义的规则。正负号由语法分析阶段处理，不属于数值 Token 本身。

支持字符转义：`\n`、`\r`、`\t`、`\0`、`\'`、`\"`、`\\`。字符不能跨行。组合字符序列可能包含多个 Unicode 码点，本系统会按多个字符拒绝。未提供字符串类型。

## 4 类型规则

| 声明类型 | 接受的初值 | 存储大小 |
| --- | --- | --- |
| int | 整数字面量，范围 -2147483648 至 2147483647 | 4 字节 |
| real | 整数或实数字面量，结果必须有限 | 8 字节 |
| char | 一个字符字面量 | 4 字节 |
| bool | true / false | 1 字节 |

real 使用 JavaScript Number（IEEE 754 双精度）表示，可能有浮点舍入和极小值下溢。仅支持 int 到 real 的数值扩展；不接受 real 到 int、数字到 bool 等隐式转换。变量无初值时保存 null，并显示“未初始化”，不会自动赋 0。

## 5 Token 种别码

| 种别码 | 类型 |
| --- | --- |
| 1 | CONST |
| 2 | TYPE |
| 10 | ID |
| 20 | INT |
| 21 | REAL |
| 22 | CHAR |
| 23 | BOOL |
| 30 | EQUAL |
| 31 | SEMI |
| 32 | SIGN |
| 40 | END |
| -1 | ERROR |
| 0 | EOF，内部使用，页面不展示 |

种别码为本项目自定，不能与指导书实验一示例表混用。每个 Token 保存 kind、code、label、raw、value、line、column。行列从 1 开始，列号按 JavaScript UTF-16 代码单元计数。CRLF/CR 统一为 LF。

## 6 数据结构

- Token 数组：词法结果与语法分析输入。
- Map 符号表索引：以名字查找已有声明，避免普通对象原型名称冲突。
- 符号记录：name、category、type、value、initialized、address、size、line。
- 诊断记录：stage、line、column、message。
- 处理记录：step、line、status、message。
- nextAddress：下一个变量可用的模拟偏移量。

## 7 核心算法

### 词法分析

顺序扫描字符并维护行列号。跳过空白和注释，按标识符、数字、字符常量、标点等规则分支识别。数值候选完整收集后再验证，避免把 `12abc` 错拆为合法数字与名字。非法输入产生 ERROR Token 及词法诊断。

### 声明分析

用递归下降方法匹配声明文法。先判断是否有 const，再读取类型和名字，按需读取等号与字面量，最后要求分号。Token 指针顺序前进，无需自动生成 LL/LR 分析表。

### 语义检查与提交

检查名字是否已定义、初值类型是否兼容、数值是否超出范围。所有检查通过后才将整条声明加入符号表。常量的地址为 null、空间为 0；变量地址为 nextAddress，之后增加对应类型大小。失败声明不保留名字，也不改变地址。

### 错误恢复

遇到错误，优先跳至分号之后；若跨行遇到新的 const 或类型关键字，则保留它作为下一条声明开头；遇到 END/EOF 停止跳过。该策略是教学语言的启发式恢复，不保证对任意混乱输入都恢复出用户原意。同一行缺少分号可能使后续内容一并跳过。

### 时间与空间

词法和声明处理以顺序扫描为主，Map 查找平均常数时间；总体通常随输入长度线性增长。展示前对诊断排序，若有 d 条诊断会增加 O(d log d) 的排序开销。保存 Token、符号及过程记录需要与输入规模相关的空间。

## 8 存储模型

从 0 开始，按声明顺序连续分配变量，不对齐。例如 int a; real b; char c; bool d; 对应地址 0、4、12、16，最终空间 17 字节。地址是模拟值，不是进程真实内存地址。

## 9 已知限制

- 多行注释不支持嵌套。
- 一条声明一个名字，常量必须有字面量初值。
- 不支持算术表达式、名字引用、数组、指针、函数、作用域嵌套。
- 仅针对固定四类类型，不是完整 C 语言。
- 不生成机器代码，也不执行通用程序。
- 导入文本限制为 512 KB；很大输入的全量 Token 表可能影响界面流畅性。
